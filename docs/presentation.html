Why this Project?

Sequence to structure

  • Peptide design often starts as a one-letter sequence, but downstream tools need structures (SMILES, 2D/3D, descriptors)
  • Goal: a small, reproducible pipeline, not a full SPPS lab informatics suite
  • Best for validation + build + quick ADME-style numbers in one place

Chemistry

Chemical model

  • 20 standard L-amino acids (IUPAC one-letter alphabet) Validated input — rejects non-standard residues
  • Linear amide coupling — C-terminal –COOH + incoming α–NH₂ RDKit reaction SMARTS with separate templates for Gly and Pro
  • Asp / Glu regioselectivity — side-chain carboxylates as methyl esters during assembly Default hydrolysis back to –COOH after chain completion
  • Inspired by Merrifield SPPS — in silico stepwise peptide growth
Implementation

Assembly algorithm

  • Validate — uppercase, strip whitespace, reject non-standard letters
  • Initialize — start chain from first residue's building-block SMILES
  • Extend — iteratively couple each residue via Gly / Pro / chiral amide SMARTS
  • Deprotect — optionally hydrolyze Asp/Glu methyl esters
  • Canonicalize — output canonical SMILES

Design

Sequence generation

  • Random — length N, uniform over 20 AAs Optional residue weighting
  • Motif repeat — e.g. RGD × 2 with N-term flank A + RGD × 2 → ARGDRGD
  • Combinatorial — vary one position in a base sequence e.g. AAAAA pos 3 with DE → 2 variants

All generated sequences pass through the same assembly pipeline as manual input — same validation, same coupling, same descriptors.

build_peptide_library processes batches and returns a library summary with aggregate statistics.

Looking ahead

Future directions

Next steps

  • Cyclic peptide support
  • Non-standard / unnatural amino acids
  • Property prediction models (solubility, permeability)
  • Integration with docking workflows

Current limitations

  • D-amino acids not yet supported
  • No cyclization or disulfide bonds
  • No post-translational modifications
  • Approximate pKa (no experimental states)
